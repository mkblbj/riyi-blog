# 日宜房产官网内容管理手册

## 登录与保存

1. 打开 https://app.pagescms.org/，点击 GitHub 登录，使用已获授权的日宜房产账号。
2. 打开私有仓库 `riyi-blog`，确认正在编辑 `main`。
3. 左侧“文章”用于写作；“官网管理”包含“品牌与外观”“首页内容”“导航菜单”“文章分类”。“官网图片”位于媒体选择区，供官网字段选图。
4. 保存后 Pages CMS 会把内容提交到 GitHub，并自动运行校验、测试、构建和正式发布。第一版没有独立预览站或额外“发布”按钮。

官网采用固定布局 `official-v1`。可以改文字、图片、链接、显隐和列表顺序，但不能自由拖拽板块，也不能输入自定义 HTML、Vue、CSS、字体或逐板块颜色。

## 品牌与外观

在“官网管理”→“品牌与外观”中可编辑：

- “网站名称”和“网站描述”：用于浏览器标题、首页、分享信息和 RSS。
- “Logo”：可留空；推荐 512×512 的透明 PNG 或 WebP。
- “主品牌色”和“辅助品牌色”：必须填写完整的六位十六进制颜色，如 `#1f6658`，不能写 `green`、`#fff` 或透明色。系统会生成浅色、深色、悬停色和可读的前景文字色。
- “布局版本”和“内容版本”：系统只读字段，请勿修改。当前只有 `official-v1`。

保存颜色后仍要在桌面、平板、手机的浅色和深色模式中检查链接、按钮和大色块是否清楚；系统只开放这两个全局颜色，不提供每个板块单独配色。

## 首页内容

在“官网管理”→“首页内容”中按固定结构编辑：

- “首页首屏”：标题、描述、Banner 图片、图片说明，以及固定三个快捷入口。Banner 推荐 1920×800；留空时自动使用辅助品牌色纯色背景。填写图片时必须同时填写能描述内容的图片说明。
- “App 下载区”：可整体显示或隐藏，可修改标题、说明、App Store 链接、Google Play 链接和微信小程序口令。两个商店地址必须是 HTTPS；口令保持 `#小程序://名称/编码` 格式。
- “核心服务区”：固定三项。每项可改显隐、标题、说明、可选配图、图片说明、按钮文字、目标和顺序。服务配图推荐 1200×675；有图时必须填写图片说明。
- “日宜优势区”：可整体显示或隐藏，固定四项；每项可改显隐、标题、说明和顺序。
- “咨询行动区”：固定三个入口，可改显隐、文字、HTTPS 地址、按钮样式和顺序；至少保留一个有效入口。
- “文章展示区”：可修改文章列表上方的眉题、标题和说明。文章是否精选、置顶以及所属分类仍在文章编辑器中设置。

关闭可选板块或项目后，页面会直接移除对应内容，不保留空白占位。三个服务、四个优势、三个行动的结构数量由系统固定，不能增删成任意数量。

首页快捷入口和服务链接有三种目标：

- “文章分类”：选择一个已启用分类，系统生成分类页地址。
- “官网页面”：填写以 `/` 开头的站内地址，如 `/about/`。
- “外部链接”：填写完整的 HTTPS 地址。

快捷入口当前只支持文章分类或外部链接；其余不适用字段保持为空。

## 导航菜单

“系统首页”始终存在，不能删除；可以修改显示名称和排列顺序。普通导航项可以新增、编辑、隐藏、排序和移除，移除导航只会删除顶部入口，不会删除目标页面、分类或文章。

导航目标规则：

- “文章分类”选择已启用分类，不手填分类网址。
- “官网页面”填写以 `/` 开头的站内路径，并在当前窗口打开。
- “外部链接”必须使用 HTTPS，可选择是否在新窗口打开。

排列顺序不要重复。桌面端超过六个一级入口时，其余入口自动收进“更多”；移动端由系统折叠菜单展示。不要为站内地址开启“新窗口打开”，否则校验会失败。

## 文章分类

分类有稳定编号和稳定网址标识。客户可新建分类、修改中文名称和说明、调整顺序、启用或停用；改名不会改变分类网址，也不会改变文章永久地址。Pages CMS 不提供分类硬删除。

停用分类前必须按顺序处理：

1. 如需替代分类，先新建并保持启用。
2. 把所有相关文章迁移到已启用分类。
3. 把导航、首页快捷入口和服务卡片中的旧分类引用改到新分类或其他有效目标。
4. 再关闭旧分类的“已启用”并保存。

如果文章、导航或首页仍引用已停用分类，构建会指出对应内容文件和分类编号并停止发布。确认所有引用已经迁移后，如确实需要物理删除分类文件，由维护人员通过 Git 提交完成；客户不要绕过后台删除文件。

## 文章、封面与正文图片

在左侧“文章”点击“新建”，填写标题、摘要、封面图、一个已启用分类、标签、作者、发布时间和正文。新文章默认是“草稿”；保存草稿会进入 GitHub，但不会出现在公开网站、站内搜索、RSS 或 sitemap。

确认正文后，把“状态”改成“已发布”并保存。发布成功后，文章地址固定为 `https://www.riyihome.com/posts/文章编号/`；以后修改标题、分类或发布时间，网址仍然不变。不再公开的文章应改为“已归档”，不要删除文件；下次发布会从 HTML、搜索、RSS 和 sitemap 移除，Git 历史仍会保留。

图片分为两个独立媒体区：

- “文章图片”：只用于文章封面和正文，文件保存在 `content/media/`。封面必填；正文图片要写能描述画面内容的说明文字，例如“东京一居室客厅”，不要只写“图片”。
- “官网图片”：只用于 Logo、Banner 和服务配图，文件保存在 `content/site-media/`。不要从文章图片区复制路径到官网字段，也不要反向混用。

两类图片均只接受 JPG、JPEG、PNG 或 WebP，单文件不得超过 10 MB。仓库保留上传原图，发布产物会自动缩放、转换为 WebP 并使用带哈希的文件名；不要手工修改生成后的地址。

## 自动发布、失败与恢复

保存会触发 GitHub Actions 的 `Deploy production`：先校验内容关系、图片、六位颜色和链接，再运行测试、构建与产物检查；通过后才上传阿里云 OSS、刷新 CDN，并检查首页、最近三篇文章和所有已启用分类页。

常见失败及处理：

- 必填项为空、颜色不是 `#RRGGBB`、链接类型与地址不匹配：回到错误指出的字段修正后重新保存。
- 图片超过 10 MB、图片不存在、配图缺少说明文字：压缩或重新选择图片并补充说明。
- 文章、导航或首页引用已停用/不存在的分类：先迁移到已启用分类。
- App 或咨询地址不是 HTTPS、小程序口令格式错误、导航顺序重复：按日志中的文件和字段修正。

内容校验、测试或构建失败时不会进入上传，线上旧版本不受影响。若错误发生在 OSS 上传、CDN 刷新或最终网址检查阶段，线上可能已收到部分新文件，不能只凭红色状态判断版本；立即联系维护人员核对。基础设施瞬时故障排除后，可点击左侧“重新部署官网”重跑同一套流程；内容错误必须先修正，严重问题由维护人员用 Git revert 恢复。

联系维护人员时提供保存时间、改动内容、GitHub Actions 运行链接和日志中的第一条错误。不要在消息、工单、Pages CMS 或仓库中发送 AccessKey、Secret、token、证书私钥或 `.env` 文件。
