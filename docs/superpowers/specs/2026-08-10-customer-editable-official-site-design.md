# 客户可编辑官网设计

## 背景

日宜房产新官网已经使用 VitePress、vitepress-theme-teek、Pages CMS、GitHub Actions 与阿里云 OSS/CDN 独立运行。现有 Pages CMS 已支持文章的封面、正文图片、分类、精选、置顶、草稿和发布，但首页宣传内容、导航与品牌视觉仍主要写在代码中。

交付后，客户需要在不接触代码的前提下维护文章与官网常用内容，包括替换图片、调整首页文案、设置文章板块、管理导航和更换暂定品牌色。现有静态站点、Git 内容和自动部署架构保持不变，不新增数据库或另一套管理后台。

## 目标

- 将 Pages CMS 从文章编辑器扩展为日宜官网内容管理入口。
- 允许客户编辑首页文字、图片、链接、显隐和有限排序。
- 允许客户管理导航菜单与文章分类，同时保护已有内容和稳定链接。
- 允许客户修改全站主品牌色和辅助品牌色。
- 保存后自动校验并发布；失败时线上旧版本不受影响。
- 将内容模型与布局实现分离，为以后新增布局预设保留兼容边界。

## 非目标

- 不实现 Wix 类自由拖拽页面生成器。
- 不允许逐个板块任意设置颜色、CSS、字体或响应式布局。
- 不引入新的 CMS、数据库、UniCloud、Vercel 或其他长期托管依赖。
- 不在第一版提供独立预览域名、审批流或多人内容工作流。
- 不允许客户删除系统首页、直接删除仍被文章引用的分类，或直接编辑 Teek/Vue 配置。

## 方案选择

### 采用：Pages CMS 结构化官网设置

在现有 `.pages.yml` 中增加官网管理分组、结构化单文件、分类集合和官网媒体库。Vue/Teek 构建层读取经过校验的内容文件并生成页面。

该方案复用现有登录、Git 历史、自动部署和阿里云环境，客户只需学习一套后台。

### 不采用：Pages CMS 自由区块生成器

区块生成器允许客户任意增删不同结构的首页板块，但会扩大校验、响应式适配和客户培训范围，不符合第一版的固定布局目标。

### 不采用：新建可视化 CMS

新的可视化 CMS 可以提供更强拖拽能力，但会增加账号、数据迁移、部署和长期维护成本，并破坏当前轻量独立架构。

## 总体架构

系统分为四层：

1. **编辑层**：Pages CMS 提供中文结构化表单和媒体选择器。
2. **内容层**：YAML 与 Markdown 文件保存官网设置、导航、分类和文章。
3. **构建层**：TypeScript 校验、解析、图片优化并生成 Teek/Vue 可消费的数据与 CSS 变量。
4. **展示层**：固定的 Vue/Teek 组件负责布局、响应式、深色模式和可访问性。

客户只修改内容层。布局层继续由开发者维护，因此以后调整组件或增加布局预设时，不需要客户重新录入内容。

## 内容和文件边界

### `content/site/settings.yml`

保存全站品牌与布局元数据：

- 网站名称
- Logo 或品牌图片
- 主品牌色
- 辅助品牌色
- `layoutPreset: official-v1`
- 内容结构版本

`layoutPreset` 和内容结构版本在第一版只读或隐藏。第一版只有 `official-v1`，以后可以加入开发者验证过的其他布局实现。

### `content/site/home.yml`

保存首页各固定板块的数据：

- 首页首屏
- App 下载区
- 核心服务区
- 日宜优势区
- 咨询行动区
- 文章展示区标题

板块结构固定。客户可以修改允许的内容、隐藏可选板块和调整有限列表顺序，不能插入任意 HTML、Vue 或 CSS。

### `content/site/navigation.yml`

保存顶部导航列表。每项包含：

- 稳定编号
- 显示名称
- 类型：系统首页、文章分类、官网页面或外部链接
- 目标分类、内部路径或外部地址
- 是否显示
- 是否新窗口打开
- 排列顺序

### `content/categories/`

每个文章分类使用独立结构化文件，包含：

- 稳定编号
- 固定 slug
- 中文显示名称
- 是否启用
- 可选说明
- 排列顺序

文章保存分类稳定标识，构建时解析为 Teek 所需的显示数据。修改分类显示名称不改变文章永久地址。分类 slug 不向普通客户开放修改。

分类集合允许客户新建和编辑，但在 Pages CMS 中禁用硬删除。客户使用“停用”代替删除；确认文章和导航均已迁移后，由维护人员通过正常 Git 提交移除分类文件。

### `content/site-media/`

官网图片与 `content/media/` 文章图片分开管理。允许 JPG、JPEG、PNG、WebP，上传时随机安全重命名，构建时继续执行压缩、WebP 转换和哈希文件名处理。

### `content/posts/`

继续保存文章 Markdown。文章编辑器把现有固定分类选择改为引用启用的分类集合，其他草稿、发布、精选、置顶和固定文章网址规则保持不变。

## Pages CMS 信息架构

在左侧增加“官网管理”分组，包含：

1. 品牌与外观
2. 首页内容
3. 导航菜单
4. 文章分类
5. 官网图片

原有“文章”和“文章图片”继续保留。客户不需要接触文件名、源码或 Git 操作。

## 客户可编辑字段

### 品牌与外观

- 网站名称
- Logo / 品牌图片
- 主品牌色
- 辅助品牌色
- 当前布局版本，只读

颜色使用 `#RRGGBB` 格式。系统根据主色和辅助色生成链接色、悬停色、浅背景、边框和深色模式变量，并自动选择合适的前景文字色。客户不能逐板块设置颜色。

### 首页首屏

- 主标题
- 副标题
- 可选 Banner 图片；留空时使用品牌色背景
- 三个快捷入口的标题、说明和目标

首屏是系统必备板块，不能整体删除。

### App 下载区

- 显示开关
- 标题和说明
- App Store 链接
- Google Play 链接
- 微信小程序口令

Apple、Google Play 和微信图标由系统维护，不向客户开放替换。

### 核心服务区

固定三张服务卡片。每张卡片支持：

- 显示开关
- 标题
- 说明
- 可选配图
- 按钮文字
- 链接
- 排列顺序

客户不能增加不受支持的卡片类型。

### 日宜优势区

- 板块显示开关
- 区域标题和说明
- 四项优势的标题、说明、显示开关和顺序

装饰图标由系统维护，保持视觉一致。

### 咨询行动区

- 区域标题和说明
- 查看房源、提交需求、微信咨询三个入口的显示开关、按钮文字和目标

系统要求至少保留一个有效的咨询或房源入口。

### 文章展示

- 首页文章区标题
- 文章分类由文章编辑器选择
- 精选和置顶继续由文章字段控制

首页和分类页自动读取文章，不要求客户重复配置文章位置。

## 导航和分类管理规则

客户可以新增、编辑、隐藏、排序和删除普通导航项。

保护规则如下：

- 系统“首页”入口不能删除，可以修改显示名称和顺序。
- 删除导航只移除顶部入口，不删除目标页面、分类或文章。
- “关于日宜”等内部页面可以从导航隐藏，但页面文件不会被客户误删。
- 导航引用分类时必须选择一个已启用分类。
- Pages CMS 不向客户提供分类硬删除操作。
- 分类停用后保留旧文章，但新文章不能再选择该分类。
- 物理删除分类前必须先迁移相关文章并解除导航引用，再由维护人员通过正常 Git 提交完成。
- 分类页和导航目标使用稳定 slug，中文显示名称可以独立修改。
- 桌面导航超过安全数量时收进“更多”，移动端继续使用折叠菜单。
- 外部导航可选择新窗口打开；内部导航强制同窗口。

## 图片规则

- 官网图片与文章图片使用独立媒体源。
- 页面字段只能选择对应媒体源中的图片。
- 单文件上限保持 10 MB。
- Banner、Logo 和服务卡片分别显示推荐尺寸及比例说明。
- 构建处理原图，仓库保留原始上传文件，产物使用优化后的 WebP。
- 可选图片缺失时使用纯色或系统占位布局；必填图片缺失时构建失败。
- 所有内容图片要求提供有意义的说明文字；纯装饰图片使用空替代文本。

## 品牌色规则

- 只开放主品牌色和辅助品牌色两个全局输入。
- 输入必须为六位十六进制颜色。
- 构建层生成派生色，不保存一组容易失去一致性的手工色值。
- 自动计算亮度并为主要色块选择深色或浅色前景文字。
- 关键文字和交互控件必须满足既定对比度检查，否则构建失败并指出字段。
- 深色模式使用派生后的安全色阶，不直接复用可能过暗的原色。

## 保存与发布流程

1. 客户使用 GitHub 账号登录 Pages CMS。
2. 客户在“官网管理”或“文章”中编辑内容。
3. 保存后 Pages CMS 向 `main` 提交内容文件和媒体。
4. GitHub Actions 运行类型检查、内容校验、图片处理、测试和 VitePress 构建。
5. 构建产物通过完整校验后上传阿里云 OSS。
6. CDN 刷新完成后执行首页、导航、分类和文章冒烟检查。
7. 全部成功后线上内容更新。

第一版不增加预览站或单独发布按钮。固定结构和严格校验负责降低误操作风险。

## 校验与失败处理

构建前检查：

- YAML 结构、必填字段、类型和文字长度
- 颜色格式与对比度
- 图片格式、大小和真实存在性
- 内部路径和分类引用
- 外部 URL 协议和微信小程序口令格式
- 重复导航编号、分类编号、slug 和排列冲突
- 系统首页存在
- 至少一个有效服务行动入口存在
- 分类停用、缺失和文章引用关系

错误消息必须指出内容文件、字段名称和修复建议，避免只显示通用构建失败。

任何内容校验、构建、上传或冒烟检查失败都会终止工作流。上传阶段沿用先资源后 HTML 的部署顺序；未通过发布门禁时不替换线上 HTML。所有修改保留 Git 历史，可通过正常 revert 回退，不使用 force push。

## 初始迁移

- 以当前生产官网的文字、链接、导航、品牌色和图片作为初始结构化数据。
- 将 `src/official-site.ts`、`src/navigation.ts`、Teek 配置和首页组件中的客户可编辑常量迁移到内容文件。
- 保留平台固定行为、图标、组件结构和默认回退值在代码中。
- 为现有分类创建稳定编号和 slug，并迁移现有文章引用。
- 迁移后生产首页在默认数据下保持视觉和链接等价，避免交付时突然改版。

## 未来布局扩展

内容文件不保存具体 CSS 或网格位置。布局实现通过 `layoutPreset` 选择：

- 第一版仅提供 `official-v1`。
- 小幅布局调整只修改 Vue 和 CSS，内容文件不变。
- 以后可新增经过桌面、移动和深色模式验证的布局预设。
- 完全自由拖拽如有真实业务需求，作为独立二期项目评估，不向当前内容模型追加任意代码字段。

## 测试与验收

### 自动化测试

- Pages CMS 配置字段、媒体源、保护操作和引用关系
- 官网设置、首页、导航和分类 schema 的成功与失败样例
- 分类新增、改名、停用、硬删除禁用和现有文章迁移
- 导航新增、修改、隐藏、删除、排序和“首页”保护
- 品牌色解析、派生色和对比度
- 图片优化、路径重写、缺失图片和超限图片
- 首页组件使用内容文件而非旧硬编码常量
- 生产构建中的导航、分类、下载入口、服务区和咨询入口
- 部署工作流在校验失败时不会进入上传阶段

### 浏览器验收

- 桌面、移动和平板宽度
- 浅色和深色模式
- 导航“更多”和移动折叠菜单
- Banner 有图与无图状态
- 板块隐藏和卡片排序
- 主品牌色和辅助品牌色切换后的可读性
- App Store、Google Play、微信小程序和咨询入口
- 文章分类选择、分类页和固定文章网址

### 生产验收

- GitHub Actions 完成且提交 SHA 与生产版本一致
- 首页、导航、所有启用分类、最新文章和静态资源返回成功
- 生产 HTML 包含当前品牌、导航和首页设置
- CDN 刷新后无旧导航或旧品牌色残留

## 客户交付

更新客户手册并包含：

- Pages CMS 登录与官网管理入口
- 首页各字段的用途
- Banner、Logo、卡片图的推荐尺寸
- 品牌色填写示例
- 导航和分类的区别
- 分类停用、文章迁移和维护人员删除流程
- 保存、自动部署、失败提示和联系维护人员的方法
- Git 历史回退由维护人员操作的说明

## 验收标准

- 客户无需代码即可完成文章、官网图片、首页内容、品牌色、导航和分类的日常维护。
- 客户不能通过普通表单破坏系统首页、删除仍被引用的分类或写入任意代码。
- 默认内容构建出的官网与当前生产版本保持等价。
- 无效修改不能替换线上稳定版本，并提供可操作的错误信息。
- 新布局可以复用现有内容数据，不要求客户重新录入。
